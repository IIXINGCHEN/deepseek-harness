## 根因与修复矩阵

| # | 根因分类 | 原始缺陷行为 | 实施修复 | 最终状态 |
|---|---|---|---|---|
| **S1** | **上游更新产物陈旧** | `start-dsh.ps1` 自检第 4 步只检查产物是否存在，不检查与 `src/` 的相对时间。上游 `git pull` 更新了源码或 preset YAML 时，构建产物保持陈旧，运行旧代码导致 schema 不匹配（如 PTC 模式旧枚举报错）。 | 在 `start-dsh.ps1` 引入 `Test-BuildArtifactsStale`，递归对比 `packages/apps/vendor` 下 `.ts`/`.tsx` 与 `lib/`/`dist/` 产物最新修改时间；检测到源码更新即自动执行 `pnpm run build`。 | **Resolved** |
| **S2** | **插件组合深度校验缺失** | 自检第 5 步仅检查重复 `insert` ID，无法拦截加载（apply）期崩溃（如插件 `config` 违反导出的 `Config` schema，或多条目同名挂载导致 `duplicate prefix route` 崩溃）。 | 升级自检第 5 步嵌入式预检脚本：① 动态加载插件模块并调用其 `Config` schema 校验条目配置，不匹配直接 exit 2 并给出修复建议；② 扫描同名多挂载条目并给出明确的 `cordis.patch.yml` 禁用建议。针对 PS5.1 特性移除了所有内部空行和双引号。 | **Resolved** |
| **S3** | **Preset 与 Schema 无测试锁定** | 上游重命名或枚举修改（如 `mode: ptc`）缺少自动化测试保证内置 preset YAML 配置始终符合插件 schema。 | 在 `packages/preset/agent-presets/tests/mount.spec.ts` 中添加 `writes tool-presentation configs the plugin schema accepts` 回归测试，并在 `package.json` 添加 `dsh-agent-tool-presentation` 依赖。 | **Resolved** |
| **S4** | **市场更新与双挂载复发链** | 插件市场 UI 开关将 `web-ui-better-sidebar` 置为 `disabled: false`，击穿 standalone 的 `!!js` 守卫；此外新发布包被 pnpm 供应链门拦截导致自检依赖修复循环失败。 | ① S2 预检提供冲突报警；② 恢复 `cordis.patch.yml` 稳定配置；③ 在 profile `pnpm-workspace.yaml` 中将新包家族加入 `minimumReleaseAgeExclude` 排除表，解除 `pnpm install` 供应链锁定。 | **Resolved** |
| **S5** | **PTC 模式切换异常** | 内存中运行旧进程导致 UI 报告 `expected "native" \| "code" \| "both" but got "ptc"`。 | S1 产物新鲜度门禁防止旧产物运行；S3 测试锁定枚举正确性；服务重新拉起后完全恢复。 | **Resolved** |
