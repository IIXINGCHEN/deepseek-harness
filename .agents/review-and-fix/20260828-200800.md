## 根因与修复说明

### 1. 根因剖析
1. **历史全局包依赖遮蔽**: 早期全局安装在 `AppData/Roaming/npm` 的旧版 `@deepseek-ai/dsh` 包含未重命名前的 `@deepseek-ai/dsh-agent-tool-presentation`，其 Config schema 仅支持 `native | code | both`。
2. **符号链接当前性比对缺陷**: `packages/boot/app-boot/src/profile.ts` 中的 `moduleFallbackEntryCurrent` 使用了原生字符串比较 `readlinkSync(link) === entry.packageDir`。在 Windows 系统上，斜杠差异或路径表达差异使得 fallback 判定逻辑未正确调用 `symlinkPointsTo` 进行规范化比较，导致 `~/.dsh/profiles/node_modules/` 中的符号链接依然指向旧版全局包。
3. **运行时配置冲突**: 当用户在前端切换至 PTC 模式预设 (`packages/preset/agent-presets/presets/ptc/agent.cordis.yml`) 时，预设声明了 `mode: ptc`，但被加载的旧版插件 Schema 将其判定为非法值并报错拦截。

### 2. 修复措施
1. **完善模块回退链接一致性判定**: 将 `packages/boot/app-boot/src/profile.ts` 中 `moduleFallbackEntryCurrent` 对 symlink 的检查升级为 `symlinkPointsTo(link, entry.packageDir)`，确保符号链接始终安全、精准地对齐当前最新仓库源码产物。
2. **执行全链路构建与回退修复**: 执行 `healProfilesModuleFallback` 将 `~/.dsh/profiles/node_modules/@deepseek-ai/*` 全部正确指向当前项目的最新构建产物 (`lib/`)。
3. **重编译并验证服务**: 执行 `pnpm run build` 生成最新产物，全链路自检 `start-dsh.ps1 check` 6 阶段全绿通过。
