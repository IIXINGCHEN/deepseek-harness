## Findings Summary

### Finding 1 [Critical - Resolved]
- **File**: `scripts/desktop-host/Program.cs`
- **Category**: Correctness / Authentication
- **Issue**: Desktop host launched `dsh web` and attempted to connect to `http://127.0.0.1:<port>` without capturing the one-time authentication token (`?token=...`). This caused the backend to reject unauthenticated loopback requests and return 404/401/redirect loops, leading to WebView2 displaying `ERR_CONNECTION_REFUSED` or timeout failure.
- **Resolution**: Subprocess standard output is now parsed asynchronously for the authenticated URL emitted by `dsh web`. Once the token URL is captured, WebView2 directly navigates to `authenticatedUrl`, setting the authentication cookie and seamlessly rendering the client interface.

### Finding 2 [Warning - Resolved]
- **File**: `scripts/package-windows-desktop.ts`
- **Category**: Deployment / Packaging Completeness
- **Issue**: Previously only copied from `python/sdk-runtime`, omitting web bundles (`dsh-web-app`), web frontend assets (`dsh-web-frontend`), native landlock bindings (`node-addon-landlock-run`), and required 3rd-party hoisted modules.
- **Resolution**: Updated `package-windows-desktop.ts` to recursively scan and materialize all workspace packages (`packages/*/*`, `apps/*`, `vendor/*`, `native/*`) and dereference 3rd-party dependencies from `.pnpm`, while excluding devDependencies to optimize package footprint.

### Finding 3 [Warning - Resolved]
- **File**: `scripts/desktop-host/Program.cs`
- **Category**: Diagnostics / Error Reporting
- **Issue**: When backend process failed to boot, `MessageBox` displayed a generic failure message without capturing Node.js stderr stack traces.
- **Resolution**: Added asynchronous stderr capture buffer and formatted failure dialog with exact stderr trace and exit codes.
