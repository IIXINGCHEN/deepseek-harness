## Findings

### Finding 1 [Critical] 打包在 ZIP 步骤必然失败，产物残缺
- **File**: `scripts/package-windows-desktop.ts`（[5/5] 步骤）
- **Issue**: `tar.exe --force-local -a -c -f "E:/UI/deepseek-harness/DeepSeek-Harness-Windows-x64.zip" ...` 双重失败：
  1. Windows 内置 bsdtar **不支持 `--force-local`**（实测报错 `Option --force-local is not supported`）；
  2. 绝对路径 `E:/...` 的冒号被 bsdtar 解析为远程主机（`Cannot connect to E: resolve failed`）。
- **Impact**: 用户侧复现——前 4 步产物保留但发布 ZIP 从未生成；失败前一次尝试改用 PowerShell `Compress-Archive` 又因目录树并发变动（用户重复运行脚本的 `rmSync`）触发 `DirectoryNotFoundException`，且该路径无法通过 drive-letter 转义根治。
- **Fix**: 改为 `execSync('tar.exe -a -c -f DeepSeek-Harness-Windows-x64.zip -C dist-desktop .', { cwd: root })` —— 全相对路径 + `cwd`，从语法层面消除盘符冒号，不依赖任何非标 flag。

### Finding 2 [Warning] NewWindowRequested 可调起任意协议处理器
- **File**: `scripts/desktop-host/Program.cs`
- **Issue**: `Process.Start(new ProcessStartInfo { FileName = args.Uri, UseShellExecute = true })` 未限制 scheme。页面内容（含模型输出渲染的链接）可提交 `ms-msdt:`、`search-ms:` 甚至自定义已注册协议，借宿主进程以用户权限执行协议处理器——经典"借壳"攻击面。
- **Fix**: 白名单 `http://` / `https://`（大小写不敏感前缀判断）后才 `UseShellExecute`，其余 scheme 一律 `Handled=true` 且不执行，静默拦截。

### Finding 3 [Privacy - Verified Safe] 发布 ZIP 不会携带用户凭证
- **核验链**（非修改项，记录证据）：
  1. 脚本 [1/5] 步骤 `rmSync(outDir)` 无条件清空 `dist-desktop/`（含上一次运行产生的 `user_data/`）；
  2. 宿主将 `DSH_HOME` 指向 `<baseDir>/user_data`，API Key / 凭证 / WebView2 Cookie 全部落在本机该目录，不写 `%USERPROFILE%\.dsh`，不进包；
  3. 打包阶段仅显式拷贝根 `package.json` 与 `pnpm-workspace.yaml`，`.env` 从不进入 `dist-desktop`；
  4. copyPackage 排除 `node_modules`、`tests/`、`.git`、`*.tsbuildinfo`。
- **结论**: 全新构建的 ZIP 不含任何密钥、Cookie、会话数据。提醒用户：**分发前不要打包已运行过应用的目录**——脚本本身已通过 [1/5] 强制清空规避。

### Finding 4 [Security - Verified Safe] 鉴权 Token 传递路径闭环在本机回环
- Token 仅经 stdout 管道（`RedirectStandardOutput`）由宿主读取，注入 WebView2 首次导航 URL；服务仅绑定 `127.0.0.1`；Cookie 为 `HttpOnly; SameSite=Strict`，30 天有效期由服务端控制。无外发路径。
