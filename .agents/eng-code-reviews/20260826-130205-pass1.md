## Detailed Findings

### [CRITICAL] start-dsh.ps1:125-136 — Port-unconstrained process sweep can kill unrelated DSH instances
- **Category**: Correctness / Security (blast radius)
- **Description**: `Get-WebPortPids` layers 1–2 correctly resolve PIDs owning `-TargetPort`, but layer 3 sweeps ALL `Win32_Process` command lines for `apps/cli/lib/bin.js web` or `dsh web` patterns and unions those PIDs into the result **with no port check**. Consequences: (a) `Stop-DshService` force-kills (`Stop-Process -Force` + `taskkill /F /T`) DSH web instances on *other* ports or from *other checkouts* — including user data-bearing sessions; (b) `Get-DshServiceStatus` reports `IsRunning=true` and prints `http://127.0.0.1:<Port>/` even when nothing listens on the target port; (c) the background-start readiness poll repeats the full-system CIM sweep every 400 ms, widening the misfire window. The function's contract ("三层探测获取监听指定端口的进程 PID") is violated by its own third layer.
- **Recommended Fix**: Resolve port-owner PIDs first (layer 1 + netstat helper); use layer 3 only to *name-resolve* candidates that are confirmed port owners; return nothing when ownership cannot be established:
```powershell
# 第 3 层: 仅对已确认占用目标端口的 PID 做命令行甄别；无法确认归属时不返回候选
$ownerPids = @(layer1 + netstat-owner-pids)
$dshProcs = Get-CimInstance Win32_Process ... | Where-Object { $ownerPids -contains $_.ProcessId }
```
