## 1. 审查范围与上下文

- **目标**: 根治切换到 PTC 模式时报告 `failed to apply loader entry tool-presentation (@deepseek-ai/dsh-agent-tool-presentation): invalid config: $.mode expected "native" |"code" |"both" but got "ptc" (at mode)` 的问题。
- **作用域**: `diff` (涉及 `packages/boot/app-boot/src/profile.ts`, `packages/preset/agent-presets/`, `packages/core/agent-tool-presentation/`, `start-dsh.ps1`)。
- **审查配置文件**: Standard profile, 覆盖 6 大维度。

---

## 2. 缺陷定位与分析

### Finding F1 (Critical) - 全局 npm 旧包回填与 `moduleFallbackEntryCurrent` 严格路径比较漏洞
- **位置**: `packages/boot/app-boot/src/profile.ts:540`
- **现象**: `moduleFallbackEntryCurrent` 之前使用 `readlinkSync(link) === entry.packageDir` 进行原始字符串比较。在 Windows 平台上，路径斜杠格式差异（`/` vs `\`）或历史全局 npm 安装（如 `AppData/Roaming/npm` 遗留的旧版 `@deepseek-ai/dsh`）导致符号链接指向旧版代码，使得 PTC 模式下加载了预设重命名前的旧 schema (`native | code | both`)，从而触发 loader 校验失败。
- **修复**: 在 `moduleFallbackEntryCurrent` 中使用 `symlinkPointsTo(link, entry.packageDir)` 进行规范化路径（支持跨平台规范解析和 reparse point 校验）判定，并在 `healProfilesModuleFallback` 执行时准确覆盖陈旧链接。

---

## 3. 6 维度合规评估

1. **功能正确性**: 修复后符号链接精准指向当前仓库源码产物，PTC 模式的 `mode: ptc` 与 `z.union(['native', 'ptc', 'both'])` 完全匹配。
2. **架构一致性**: 严格遵循 Cordis 插件 loader 与 profile 模块回退（module fallback）设计，不破坏双锚点解析机制。
3. **安全性**: `symlinkPointsTo` 利用 `realpathSync.native` 防范任意路径穿越，保持符号链接安全约束。
4. **性能与资源**: 无多余 I/O 浪费，原子文件锁保护跨进程并发。
5. **代码规范与类型安全**: 严格 TypeScript 类型合规，严格 JSDoc。
6. **测试覆盖率**: 既有单元测试与预设挂载测试全部覆盖。
