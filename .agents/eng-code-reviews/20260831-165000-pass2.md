## Findings

### Finding 1 [Critical] 单文件 exe 启动即失败：闭包清单漏登 peer
- **Symptom**: `dsh-runtime.exe web --port 3080` 直接失败：
  `Cannot find package '@deepseek-ai/dsh-session-title-llm' imported from .../dsh-session-title-first-prompt-llm/lib/index.js`
- **Root cause 链**（每步有实测证据）：
  1. `base/cordis.patch.yml:55` 加载 `dsh-session-title-first-prompt-llm`；
  2. 该包的 `dsh-session-title-llm` 是 **peerDependency**（源 package.json）；
  3. 部署用 `--config.auto-install-peers=false`，仓库契约是"运行时清单供应每个 peer"（build 脚本注释原文）；
  4. `python/sdk-runtime/package.json` 未列该 peer → staged 树缺失 → ESM 裸名解析失败。
- **Second gap（同机制，预杀手）**: `dsh-util-workspace-path`（`dsh-api-session-controller` 的 peer）同样缺登——web profile 加载 API 会话控制器时会以相同方式失败。
- **Fix**: 闭包清单补两行 `"workspace:^"`：`dsh-session-title-llm`、`dsh-util-workspace-path`。
- **系统性核验**: 写了 peer+dep 双维度 staged 树扫描器，修复前恰报 2 个缺口（即上述两者），无第三个。

### Finding 2 [Warning] Windows 下 pkg 管线入口环境缺失
- **Symptom**: 裸跑 `pnpm exec tsx scripts/build-exe-for-python-sdk.ts` 报 `pnpm must expose a JavaScript entrypoint through npm_execpath or PNPM_HOME on Windows`。
- **Root cause**: 本机 pnpm 经 corepack `.CMD` shim 暴露，`PNPM_HOME` 下只有 store 无 bin。
- **Fix**: 桌面打包脚本内置 `exeBuildEnv()`——检测 `node_modules/corepack/dist/pnpm.js` 并注入 `npm_execpath`（不改动仓库既有 exe 构建脚本）。

### Finding 3 [Info] 旧拷贝树 404 与本缺陷同类
- 旧方案"手工物化目录树"依赖 pnpm dev 链接布局的偶然完整性；peer 缺失类问题在拷贝树上表现为静默 404（fallback 链断），在 pkg 单文件上表现为 fail-loud 报错——后者可诊断、可修复，印证弃用旧方案的决策。
